02 / The Problem

Everyday food questions are deceptively hard

01

Generic answers miss local context

Egyptian dishes have regional names, Arabic spellings, local household measures, and different cooking states.

02

LLMs are fluent, not necessarily factual

A confident response can still contain an invented calorie value, a merged ingredient, or an untraceable source.

03

Nutrition is a calculation problem

Ingredients, quantities, edible portions, cooking yields, nutrient profiles, and serving bases must agree.

The design challenge

How do we make a conversational system useful without allowing it to guess?

We separate retrieval, computation, routing, safety, and wording into explicit boundaries. Each boundary can be tested and audited independently.

03
03 / Product Thesis

Trust is an architecture decision

01

Deterministic arithmetic

Every calorie, macro, sodium, and comparison value comes from application code, not model memory.

02

Provenance by default

Recipes, nutrient records, factors, and guidelines carry source and version information.

03

Fail closed when evidence is missing

Unknown remains null. Ambiguous data becomes a review item. Unsupported requests receive a refusal or clarification.

04

Safety before intelligence

Medical, emergency, injection, and guarantee requests are intercepted before planning, retrieval, or optional LLM calls.

RAG finds context. It does not become numeric authority.

Retrieval is descriptive

  • It locates recipes and guidance.
  • It carries document provenance.
  • It applies approval and verification filters.

Calculation is authoritative

  • It uses structured data and factors.
  • It is independent from generated prose.
  • It fails closed on missing evidence.

09 / Safety and Integrity

Useful intelligence inside explicit boundaries

Medical safety precedence

Diagnosis, treatment, emergencies, and personalized medical advice route to fixed safe handling before any optional model call.

Prompt injection defense

Request-integrity controls block attempts to override numeric results, use unapproved data, or change system behavior.

Grounded formatting

Every number and dataset entity in optional model wording must be traceable to the structured facts. Otherwise, the deterministic template is restored.

Privacy-safe observability

Logs and debug traces expose routes, timings, and statuses without serving raw user messages or health information.

Secure API boundary

Strict schemas, body-size limits, content-type checks, rate limiting, origin checks, security headers, request IDs, and timeouts.

Fail-closed deployment

The synthetic graduation demo refuses to start in production. Release gates distinguish engineering readiness from real deployment evidence.

14 / Honest Scope

The graduation demo is ready for review. Production is a separate gate.

What the demo proves

  • The architecture works end-to-end locally.
  • Numbers are reproducible and traceable.
  • Ambiguity and missing data are handled explicitly.
  • Safety and API boundaries are enforced in code.
  • The evaluation and regression workflow can be rerun.

What still requires external work

  • Human approval of recipe, ingredient, conversion, and nutrient records.
  • Real Egyptian-Arabic user evaluation and wording review.
  • Staging pilot with consent and signed feedback report.
  • Approved credentials, infrastructure, rollback evidence, and deployment authority.

The right claim: deterministic, traceable, graduation-ready. Not “100% accurate” and not “production approved.”
